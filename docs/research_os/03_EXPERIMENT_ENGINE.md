# 03. Experiment Engine: Sandboxing and Determinism

In a world-class Quantitative Research Organization, an experiment is not just "running a Python backtest script." It is a rigorous, controlled physical-like experiment. This document details how the **AlphaAlgo Experiment Engine** enforces environment isolation, resource control, and deterministic execution.

---

## 1. Sandbox Isolation Principles

To prevent experiments from interfering with one another, corrupting datasets, or leaking state, all trial runs are executed in isolated **Sandbox Environments**.

### Sandbox Constraints
1. **No External Network Access:** Sandboxes are completely isolated from the internet during backtests. This prevents model code from querying external APIs (which could leak future data or create look-ahead dependencies) and stops live broker interactions.
2. **Resource Caps:** Every experiment run is constrained by hard resource ceilings:
   * **Memory Limits:** Prevent memory exhaustion and swap thrashing.
   * **CPU Cores:** Bounded thread pool allocation to ensure fair scheduling across parallel runs.
   * **Wall-Clock Timeout:** If a backtest runs longer than the allocated limit, it is forcefully terminated and logged as a failure.
3. **Immutable Input Mounting:** Historical datasets are mounted to the sandbox as **read-only volumes**. Under no circumstances can an experiment script write to, modify, or overwrite raw data.

---

## 2. Configuration Hashing

Every experiment run is defined by a single, declarative configuration object. The Research OS computes a unique **SHA-256 Configuration Hash** over this object before launching the trial.

```
+-----------------------------------+
| Experiment Configuration JSON     |
| - Model Parameters                |
| - Feature Configurations          |
| - Dataset Version                 |
| - Seed & Environment Specs        |
+-----------------+-----------------+
                  |
                  v  [Canonical JSON Serialization]
+-----------------+-----------------+
                  |  SHA-256
                  v
+-----------------+-----------------+
| Config Hash: `0f4b23ca...`        |
+-----------------------------------+
```

### Hash Verification Rules
* If the configuration hash matches a previously executed experiment in the **Experiment Registry**, the system **skips execution** and immediately returns the cached results. This prevents duplicate computational waste (similar to compiler caching).
* Any change to model hyperparameters, source code, data version, or feature selections results in a different configuration hash, forcing a new isolated run.

---

## 3. The Experiment Registry

The **Experiment Registry** is an immutable database table that stores the results of all completed trials. It serves as the institutional memory for both successful and failed research paths.

### Schema Fields
* `experiment_id`: Unique UUID generated by the orchestrator.
* `config_hash`: Unique SHA-256 configuration hash.
* `hypothesis_id`: Foreign key pointing to the pre-registered hypothesis.
* `dataset_id`: Foreign key pointing to the immutable dataset record.
* `status`: "PENDING" | "RUNNING" | "COMPLETED" | "FAILED".
* `reproducibility_package`: JSON mapping containing Python version, platform, package lock, and exact git commit SHA of the execution harness.
* `metrics`: Standard backtest metrics (e.g., Annualized Return, Volatility, Sharpe Ratio, Max Drawdown, Turnover).
* `performance_time_series_path`: Path to an immutable storage file (Parquet or Feather format) containing the daily returns, weights, and positions.
* `error_log`: Captured traceback in case of a failure status.

---

## 4. Deterministic Replay Protocol

A core failure of amateur quantitative research is the inability to reproduce a backtest result. The AlphaAlgo Research OS guarantees reproducibility through its **Deterministic Replay Protocol**:

1. **Seed Enforcement:** All random number generators (numpy, pandas, torch, random) are seeded before running the trial code.
2. **Deterministic Sort:** When fetching data or executing joins, SQL query results or pandas operations are ordered explicitly (e.g., `sort_values` with stable algorithms) to prevent non-deterministic multi-threaded ordering.
3. **Environment Tracking:** The execution engine checks that the runtime environment exactly matches the recorded `reproducibility_package`. If a library mismatch is found, it refuses to run and flags a warning.

By enforcing these constraints, anyone—or any automated agent—can rerun a years-old experiment and achieve the exact same performance metrics to the decimal point.
